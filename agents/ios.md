# iOS — Agent Instructions

## Info.plist Configuration

- **Define all Info.plist values in `app.config.js`** under `expo.ios.infoPlist`. Never edit `ios/App/Info.plist` directly — it gets regenerated by `expo prebuild`.
- **Add all required usage description strings.** Every iOS privacy API must include a purpose string. Common examples:
  - `NSCameraUsageDescription` — "This app uses the camera to [feature description]."
  - `NSPhotoLibraryUsageDescription` — "This app needs access to your photo library to [feature description]."
  - `NSLocationWhenInUseUsageDescription` — "This app uses your location to [feature description]."
  - `NSFaceIDUsageDescription` — "This app uses Face ID to authenticate you."
  - `NSMicrophoneUsageDescription` — "This app uses the microphone to [feature description]."
  - `NSContactsUsageDescription` — "This app accesses your contacts to [feature description]."
- **Keep descriptions concise and specific** to the feature that uses the permission. Generic descriptions like "for app functionality" will be rejected by App Store Review.
- **Use `expo.ios.infoPlist.UIBackgroundModes`** for background capabilities: `audio`, `location`, `fetch`, `remote-notification`, `processing`.
- **Set `expo.ios.infoPlist.LSApplicationQueriesSchemes`** when the app needs to check if other apps are installed via `canOpenURL:`.

## Privacy Descriptions

- **Audit all privacy-related APIs used** in the codebase and ensure each has a corresponding usage description string. This includes camera, photo library, location, calendar, reminders, Bluetooth, microphone, speech recognition, health data, and Face ID.
- **Use `expo.ios.infoPlist.NSPrivacyTracking`** and `expo.ios.infoPlist.NSPrivacyTrackingDomains` for apps that collect data for tracking (iOS 14.5+). This triggers the App Tracking Transparency prompt.
- **Use `expo.ios.infoPlist.NSPrivacyCollectedDataTypes`** to declare data collection categories in the app's privacy manifest (required for App Store submission).
- **Create a `PrivacyInfo.xcprivacy`** file (or configure via config plugin) for privacy manifests required by Apple starting Spring 2024. This must list all third-party SDKs that collect data and the data types they collect.

## Capabilities

- **Enable capabilities in `app.config.js`** under `expo.ios.entitlements`. Never enable capabilities directly in Xcode.
- **Common entitlements:**
  - `com.apple.developer.applesignin` — Sign in with Apple
  - `com.apple.developer.push-notifications` — Push notifications
  - `com.apple.developer.associated-domains` — Universal links (format: `applinks:example.com`)
  - `com.apple.developer.icloud-services` — iCloud
  - `com.apple.developer.payment-pass-provisioning` — Apple Wallet
- **Add associated domains** for universal links under `expo.ios.associatedDomains` (an array of strings prefixed with `applinks:` or `activitycontinuation:`).
- **Enable keychain sharing** via `expo.ios.entitlements['keychain-access-groups']` when the app needs to share credentials with other apps or extensions.

## Native Modules

- **Prefer Expo-compatible native modules** (those listed in `expo install`). Only use bare React Native modules when no Expo-compatible alternative exists.
- **Use Config Plugins** to configure bare native modules. Never modify the `ios/` directory manually, as it gets regenerated by `expo prebuild`.
- **When using a bare native module**, create a Config Plugin that adds the necessary podspec reference, Info.plist entries, and source files.
- **Use `expo-dev-client`** for local development with custom native modules. Run `npx expo run:ios` after adding new native modules to regenerate native code.
- **Handle iOS-specific edge cases** for native modules: main thread vs. background thread initialization, memory warnings, and app lifecycle events.

## Human Interface Guidelines (HIG)

- **Use system fonts** (`SF Pro` on iOS). Do not embed custom fonts for UI text. Custom fonts are acceptable for branding elements (logos, headers).
- **Use `SF Symbols`** for icons where possible. Import SF Symbols as system images: `Image(systemName: "person.circle")` in Swift, or `@expo/vector-icons` with Ionicons in Expo.
- **Respect the safe area** on all screen designs. Use `<SafeAreaView>` from `react-native-safe-area-context` and `useSafeAreaInsets()` for precise control. Never assume the status bar or notch dimensions.
- **Follow the standard navigation patterns:** tab bars at the bottom, navigation bars at the top, modal presentations for temporary tasks.
- **Support Dynamic Type** by using `adjustsFontSizeToFit` or relative font sizing. Do not hardcode font sizes in absolute points.
- **Use `UIImpactFeedbackGenerator` / `UINotificationFeedbackGenerator`** (via `expo-haptics`) for subtle haptic feedback on key interactions.
- **Support Dark Mode** using the system color system (`SystemBackground`, `Label`, `SecondaryLabel`). Test all screens in both light and dark mode.
- **Ensure minimum touch targets of 44x44 points** for all interactive elements.

## App Store Review

- **Test on all device sizes** before submission: iPhone SE, iPhone 15/16 Pro Max, iPad. Use Xcode simulators for coverage. Test on a physical device for camera, location, and performance.
- **Do not include hidden functionality**, unfinished features, or debug menus in production builds. Remove all `__DEV__`-gated debug tools.
- **Include a demo account** in the review notes if the app requires authentication. Provide the credentials in the App Store Connect review information section.
- **Handle network errors gracefully.** The app must not crash or show raw error messages when offline. Show a friendly offline state with a retry button.
- **Test with a fresh device** (no existing data) to ensure the first-launch experience is complete and functional.
- **Use `npx eas build --platform ios --profile production`** for the final submission build. Test the build binary on a physical device before uploading to App Store Connect.
- **Use TestFlight** for beta testing. Distribute to internal testers before submitting to App Store Review.
- **Ensure all third-party SDKs comply with Apple's privacy requirements.** Remove any SDKs that use private APIs or collect data without user consent.

## Build Settings

- **Set `expo.ios.deploymentTarget`** to the minimum iOS version the app supports. Use `expo-build-properties` plugin to configure this. Default minimum: iOS 15.1 (as of 2024).
- **Configure bitcode** via `expo-build-properties`: `ios.flipper` (disable for release), `ios.useFrameworks` (set to `static` for faster builds).
- **Enable compiler optimizations** for release builds via `expo-build-properties`: `ios.deploymentTarget` and `ios.buildConfiguration`.
