# Android — Agent Instructions

## Manifest Configuration

- **Define all Android manifest values in `app.config.js`** under `expo.android`. Never edit `android/app/src/main/AndroidManifest.xml` directly — it gets regenerated by `expo prebuild`.
- **Use `expo.android.package`** to set the Android application ID (e.g., `com.meadow.app`). This must be unique and is typically the reverse domain of the app. Once published to Google Play, changing the package name requires a new app listing.
- **Set `expo.android.versionCode`** as an integer that increments for every build submitted to Google Play. Use `app.config.js` with `process.env` or a build script to auto-increment.
- **Use `expo.android.intentFilters`** to declare deep link URL patterns. Each intent filter must include `<action android:name="android.intent.action.VIEW"/>`, `<category android:name="android.intent.category.DEFAULT"/>`, and `<category android:name="android.intent.category.BROWSABLE"/>` with the appropriate `<data>` tags.
- **Use `expo.android.adaptiveIcon`** for configuring adaptive icons (foreground and background layers). Never rely on a single flat icon — Google Play requires adaptive icons for all apps.
- **Use `expo.android.splash`** for splash screen configuration. Provide a `backgroundColor` and either a `resizeMode` or a `mdpi/hdpi/xhdpi/xxhdpi/xxxhdpi` image set.
- **Use `expo.android.config`** to declare Google Maps API keys (`android:value="@string/google_maps_key"`).
- **Use `expo.ios.config`** for Google Maps on iOS counterpart, keeping Android config in `expo.android.config`.

## Permissions

- **Declare all permissions in `expo.android.permissions`** array (strings). Never add permissions to the raw manifest file.
- **Only request permissions the app actually uses.** The Play Store shows all declared permissions to users. Unnecessary permissions lead to poor reviews and may trigger policy review.
- **Common permissions and when to use them:**
  - `CAMERA` — Photo/video capture, QR code scanning
  - `ACCESS_FINE_LOCATION` — Precise GPS location
  - `ACCESS_COARSE_LOCATION` — Approximate location (network-based)
  - `READ_EXTERNAL_STORAGE` / `WRITE_EXTERNAL_STORAGE` — File access (Android < 10)
  - `READ_MEDIA_IMAGES` / `READ_MEDIA_VIDEO` / `READ_MEDIA_AUDIO` — Granular media access (Android 10+)
  - `POST_NOTIFICATIONS` — Notification permission (Android 13+)
  - `BLUETOOTH_CONNECT` / `BLUETOOTH_SCAN` — Bluetooth operations (Android 12+)
  - `RECORD_AUDIO` — Audio recording
  - `INTERNET` — Default for most apps, usually auto-added by Expo
- **Use `expo.android.permissions` for install-time permissions** only. Runtime permissions must also be requested at runtime using `PermissionsAndroid` from `react-native` or `expo-permissions` (for Expo-compatible APIs).
- **Access `AndroidManifest.xml` additions** through a config plugin when the permission is not in the standard `expo.android.permissions` list (e.g., custom `<uses-feature>` declarations).

## Adaptive Icons

- **Provide both foreground and background layers** for adaptive icons. Use `expo.android.adaptiveIcon.foregroundImage` and `expo.android.adaptiveIcon.backgroundImage`.
- **The foreground layer** should be a 108x108dp image in a 72dp viewport (centered with 18dp padding). Use a transparent background for the foreground image.
- **The background layer** should be a solid color or simple pattern. Use `expo.android.adaptiveIcon.backgroundColor` as a shortcut if the background is a flat color.
- **Provide legacy (pre-adaptive) icons** via `expo.android.icon` as a fallback for devices running Android < 8.0 (API < 26).
- **Generate all icon densities** from a single 1024x1024px source using a tool like `npx expo generate-icons` or a Figma plugin. The required densities are: mdpi (48x48), hdpi (72x72), xhdpi (96x96), xxhdpi (144x144), xxxhdpi (192x192).

## Google Play Requirements

- **Target API level requirements:** As of August 2024, new apps must target Android 14 (API level 34) or higher. App updates must target Android 14 (API level 34) or higher by August 2025. Use `expo-build-properties` plugin to set `android.compileSdkVersion` and `android.targetSdkVersion`.
- **Use `expo.android.minSdkVersion`** (via `expo-build-properties`) to set the minimum supported Android version. Default: 23 (Android 6.0). Consider raising to 26 (Android 8.0) for reduced fragmentation.
- **Provide a privacy policy URL** in `app.config.js` under `expo.android.intentFilters` or set in the Google Play Console. Apps that handle personal or sensitive user data must link to a privacy policy on the app's store listing.
- **Add a `Data safety` section** in the Google Play Console declaring what data the app collects and how it's used. This must match the app's actual data collection behavior.
- **Use Play Asset Delivery** or **Play Feature Delivery** for large APKs (>150MB). Configure in `eas.json` under `android.buildType` with `"apk"` or `"aab"`. AAB format is required for Google Play.
- **Use `Google Play App Signing`** — EAS Build handles this by default when configured with the correct keystore credentials.
- **Test with `npx eas build --platform android --profile production`** and install the generated APK/AAB on a physical device (or emulator) before uploading to Google Play Console.
- **Use Google Play Console's pre-launch report** to identify crashes, ANRs, and compatibility issues on a range of physical devices before release.

## Build Configuration

- **Use `expo-build-properties`** plugin for common Android build settings:
  - `android.compileSdkVersion` — Set to 34 (Android 14) as of 2024
  - `android.targetSdkVersion` — Must meet Google Play minimum target requirement
  - `android.minSdkVersion` — Set based on app requirements
  - `android.kotlinVersion` — Keep consistent with SDK requirements
  - `android.packagingOptions` — Resolve duplicate file conflicts in dependencies
- **Configure ProGuard / R8** rules via `expo-build-properties` when enabling minification. Add keep rules for serialization libraries (gson, moshi), reflection-based libraries, and native method references.
- **Use `expo.android.jsc`** or `expo.android.hermes` to set the JavaScript engine. Hermes is recommended for production (faster startup, smaller bundle). Enable it with `expo.jsEngine: "hermes"` in `app.config.js`.

## Deep Linking

- **Register Android App Links** for production deep linking by generating a Digital Asset Links file (`assetlinks.json`) and placing it at `https://[domain]/.well-known/assetlinks.json`.
- **Use `expo.android.intentFilters`** to declare the URL patterns the app handles. Each pattern must include `autoVerify="true"` for Android App Link verification.
- **Test deep links** with `npx uri-scheme open meadow://path --android` and `adb shell am start -W -a android.intent.action.VIEW -d "meadow://path"`.
- **Handle incoming deep links** in the root layout using `Linking.addEventListener`. Expo Router handles this automatically when configured via `expo.scheme`.

## Google Services

- **Use `expo-google-sign-in`** or `expo-auth-session` for Google Sign-In. Configure the OAuth 2.0 client ID in `app.config.js` under `expo.android.config.googleSignIn`.
- **Use `expo-google-maps`** or `react-native-maps` for Google Maps. Set the API key in `expo.android.config.googleMaps.apiKey`.
- **Configure Google Play Services** for features like Google Pay, Google Fit, or Firebase. The `expo-dev-client` handles this when native modules are added.
- **Enable Firebase Cloud Messaging (FCM)** for push notifications. Place `google-services.json` in the project root and reference it in `app.config.js` under `expo.android.googleServicesFile`.

## Localization

- **Use `expo-localization`** for detecting the device locale. Do not rely on Android's `Locale` class directly.
- **Provide string resources** for all user-facing text. Use `expo-localization` to determine the locale and load appropriate strings from `src/i18n/`.
- **Support Right-to-Left (RTL) layouts** when the app targets Arabic, Hebrew, or other RTL languages. Set `expo.android.supportsRtl` to `true` in `app.config.js`.
